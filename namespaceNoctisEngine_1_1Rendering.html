Describes different flags a buffer can have.

Enumerator
NONE 

This flag means the buffer will not have any special behaviour. It also means it can't be mapped.

MAP_READ_BIT 

This flag allows the buffer to be mapped for CPU reading.

MAP_WRITE_BIT 

This flag allows the buffer to be mapped for CPU writing.

MAP_PERSISTENT_BIT 

This flag allows the buffer to remain mapped while the GPU is also using it This allows you to not unbind it each time you need the GPU to use it.

Warning
requires MAP_READ_BIT or MAP_WRITE_BIT to be set
MAP_COHERENT_BIT 

This flag guarantees writes/reads between CPU and GPU stay automatically visible to each other without needing explicit memory barriers.

Warning
Requires MAP_PERSISTENT_BIT to be set
DYNAMIC_STORAGE_BIT 

This flag allows the buffer's contents to be updated later via write()

CLIENT_STORAGE_BIT 

This flag is hint to the driver that it should prefer keeping the buffer's backing storage in CPU useful when CPU access is more frequent than GPU access.

enum class NoctisEngine::Rendering::BufferMapAccess : std::uint32_t

Describes how to map a buffer to RAM.

Enumerator
NONE 

This is an invalid map access used when a buffer is unmapped.

Warning
DO NOT USE WHEN MAPPING BUFFERS
MAP_READ_BIT 

This flag allows the buffer to be mapped for CPU reading.

MAP_WRITE_BIT 

This flag allows the buffer to be mapped for CPU writing.

MAP_PERSISTENT_BIT 

This flag allows the buffer to remain mapped while the GPU is also using it. This allows you to not unbind it each time you need the GPU to use it.

Warning
requires MAP_READ_BIT or MAP_WRITE_BIT to be set
MAP_COHERENT_BIT 

This flag guarantees writes/reads between CPU and GPU stay automatically visible to each other without needing explicit memory barriers.

Warning
Requires MAP_PERSISTENT_BIT to be set
MAP_INVALIDATE_RANGE_BIT 

This flag ndicates that the previous contents of the specified range may be discarded. Data within this range are undefined except for data written after the map. No OpenGL error will be generated if discarded data is read, but doing so may result in undefined behaviour or crashes.

Warning
Requires MAP_READ_BIT to not be set
MAP_INVALIDATE_BUFFER_BIT 

This flag indicates that the previous contents of the entire buffer may be discarded. Data within this range are undefined except for data written after the map. No OpenGL error will be generated if discarded data is read, but doing so may result in undefined behaviour or crashes.

Warning
Requires MAP_READ_BIT to not be set
MAP_FLUSH_EXPLICIT_BIT 

This flag allows you to explicitly tell the driver which byte ranges were actually modified in the buffer when unmapping it. This is useful if you map a large buffer but only write to a small portion of it. It allows the driver to only sync the modified range(s). Ranges that were modified but weren't flushed are undefined. Use GPUBuffer::flush_mapped_buffer_ranges() to specify the modified ranges.

Warning
Requires MAP_WRITE_BIT to be set
MAP_UNSYNCHRONIZED_BIT 

This flag tells the driver to skip synchronization steps when mapping the buffer, even if the GPU is still using the buffer. This may result in undefined behaviour, race conditions, corrupted memory, ... Use really carefully.

◆ ShaderType

enum class NoctisEngine::Rendering::ShaderType
strong

Represents different shader types.

Enumerator
VERTEX 

Runs once per vertex. Controls where vertices are draw on the screen.

Warning
This shader is mandatory for draw calls
FRAGMENT 

Runs once per fragment (per pixel that covers a meshe's primitives) Computes the final color output.

Warning
This shader is mandatory for draw calls
GEOMETRY 

Runs once per primitive (point, line, or triangle) rather than per vertex. Can emit zero, one, or many primitives from each input primitive. Not mandatory for draw calls.

COMPUTE 

Not part of the drawing pipeline at all. Runs arbitrary parallel work on the GPU. This shader should be used in a ComputeProgram.
